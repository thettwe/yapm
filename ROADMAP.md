# yapm — Roadmap

Scope decisions from the v1 scoping session (2026-07-23). Each item becomes an OpenSpec change (`openspec/changes/`) when its turn comes — proposals are written just-in-time, not upfront.

## V1 scope (locked)

**Shape**: one workspace per instance → teams → issues. Roles: admin / member / viewer (viewer free and unlimited).
**Tracking**: issues (status, priority, labels, assignee, TipTap description, comments) · cycles with auto-rollover · triage inbox · lightweight projects (name, lead, target date, membership, computed progress).
**Surfaces**: keyboard-first list · board · roadmap (timeline of projects) · command palette · search/filtering.
**Wedge proof**: GitHub App — branch/PR ↔ issue linking, PR state drives issue status **for teams that opt in** (off by default; the divergence flag is what happens otherwise), PR + checks visible on the issue.

**Opinionated defaults (not asked, decided per philosophy):** fixed status categories (Backlog / Todo / In Progress / In Review / Done / Canceled); estimates deferred; sub-issues deferred; notifications = in-app inbox + email for mentions/assignments.

| 13 | `search` | **Instant-then-complete search**: a shared ranking core in `packages/schema`, a local pass over already-synced rows that answers on the keystroke with no network, and a Postgres full-text pass (server-only `search_document` sidecar + GIN expression index in migration **`0015_search`**, no new container and **no `CREATE EXTENSION`** — `pg_trgm` refused, since some managed-Postgres hosts cannot grant it) that extends it with comment bodies and other teams' issues under the same team-scoped predicate as the synced queries. **The maintainer answered H10 against the original plan:** the index is *not* maintained in the server-mutator wrapper — it is a pg-boss job on the existing scheduler, accepting ~10s of staleness so an issue-title edit stays inside the sub-100ms budget (deletion is the one exception, an FK cascade in the deleting transaction, so deleted text is never findable). H12 answered "show the seam": two labelled groups, `On this device` and `From the server`, never merged, so a late server answer can only ever append — the palette takes filtering and ordering off `cmdk` and anchors its cursor to a row identity. H9: text config `simple`, not `english`, via `SEARCH_TEXT_CONFIG`, with the job rebuilding the one expression index when it changes. H11: `needs_triage` and `canceled` issues are returned, visibly labelled. One entry point: Cmd-K's "Jump to issue" group is replaced, Enter on `Search everything →` opens a full `/search?q=` route. The route refuses to be a **permission oracle** — miss, out-of-scope, blank/short/unparseable query and statement timeout all return byte-identical `200`s. **Queries are never logged**, asserted by a test, and `search_document` is never an AI data source | ✅ built (feat/search) |
| 14 | `auto-status` | **The last inch of the wedge: PR state actually drives issue status** — opt-in **per team**, off by default, so an instance that adopts nothing is byte-identical to before. Two transitions and only two (linked PR `open` → In Review, `merged` → Done), justified against the fixed status set; `draft` and closed-unmerged are declined rather than deferred. Forward-only along Backlog → Todo → In Progress → In Review → Done, never onto or over `canceled`, never onto an untriaged issue. One nullable column carries both the switch and its **epoch** (`team.auto_status_since`): an event older than the instant you enabled it can never drive status, so first-install backfill and the reconcile sweep cannot retroactively rewrite a mature board. A human's status write wins whenever it is newer than the **event's own** timestamp — a comparison, not a grace window (`issue.last_human_status_at`, backfilled from `updated_at`, stamped by every status-writing mutator **except** the system principal, which is the machine-readable record that a write was not a person's). Fires on a state **edge**, never a state, so redelivery, ETag reconciliation and pg-boss retries are idempotent for free. The write goes through the shared `issue.setStatus` mutator under the **system principal** promoted out of `apps/server/src/jobs/cycles.ts` into `packages/schema` — never attributed to the PR's author — and the whole decision lives behind the `WorkGraphMutation` union, so `apps/server/src/connectors/github/` is not touched at all and a GitLab connector inherits automation with no feature-code change. **Divergence is unchanged and is the fallback by construction**: quiet when a transition fires (nothing left to disagree about), firing when automation is off *or blocked*. Migration **`0016_auto_status`**, an admin-only *Status automation* section on `/settings/connectors`, and **no new container, job, env var, or GitHub App scope** | ✅ built (feat/auto-status) |
| 15 | `attachments` | **Provider-neutral storage seam** (`StorageProvider`, shaped like `Mailer` — `put`/`get`/`delete`/`health` and deliberately **no `getUrl()`**) with a local-filesystem implementation that is the complete default and optional S3 via `aws4fetch` — no vendor SDK, no fourth container, `S3_ENDPOINT` covering R2/B2/Garage/an existing MinIO. Upload, serve, attach-once and idempotent-delete routes under `/api/v1/files`, migration **`0017_attachments`** (one table, `team_id` as the permission anchor and `teamScoped` join target, `ON DELETE SET NULL` on both edges so a deleted comment *orphans* its files instead of cascading), `sharp` thumbnails at upload — the first native module in the runtime image — and an orphan GC sweep as a fourth block on the **existing** pg-boss scheduler. Content type is **sniffed from the bytes against a five-format raster allowlist**, never taken from the upload's claim, so an SVG is served as `application/octet-stream` + `Content-Disposition: attachment` and never rendered in-origin. **No signed URLs, ever**: an `<img src>` in a Zero-synced document replicates to every client's IndexedDB, so the stored node carries an opaque id and the app proxies bytes for both providers — which is also what makes the permission check the same code either way, guarded by a CI grep that fails on a presign-shaped name or a seam member beyond the four. The read path refuses like `search`: a member of another team asking for a real id gets a response **byte-identical** to one for an id that never existed. **The rows sync but there is no `attachment` mutator anywhere** — a row without bytes is meaningless and a Zero mutator cannot carry one, so a client cannot forge a row and the derived agent-tool registry gains nothing it could call | ✅ built (feat/attachments) |

A down payment on the export gap — it builds and proves the serialiser | 📋 scoped |

**Where v1 actually stands.** The **PM core** (changes 1–7 plus `design-system`) is complete: workspace/auth, design system, issues, board, cycles, triage, and projects with a roadmap. With `connectors` (8) the delivery-truth wedge is live — GitHub PR/CI/deploy state feeds the issue-row reality strip and divergence flag. With `ai` (9) the BYO-key AI foundation and its first flagship, the team-internal cycle digest, are in. With `retro-board` (10) the team has the surface where it decides what to change, shipping with no AI in it at all. With `notifications` (11) the work graph can finally reach a person: a self-scoped inbox, and the provider-neutral mailer the rest of the product's outbound email now goes through. With `mentions` (12) a person can be reached *by name*, and the issue they were named on keeps reaching them until they say stop. With `search` (13) the last locked-scope surface is in: instant on-device, completed by Postgres full-text, in two labelled groups — and with no query recorded anywhere. With `auto-status` (14) the wedge line's middle clause is true for the first time: a linked PR opening or merging actually moves the issue, for the teams that ask for it — and for every team that does not, the divergence flag remains exactly what it was, which is the whole reason the switch exists.

**V1 is now complete.** Three things the locked scope above names had never been built, and saying "V1 PM core complete" obscured them. All three are now closed:

- **Notifications** — "opinionated defaults" commits to "in-app inbox + email for mentions/assignments". Closed by changes 11 and 12: the in-app inbox, the assignment and comment triggers, and batched email ship in 11 (and `SMTP_URL` finally has a consumer); the *mentions* half of that sentence ships in 12, which turned out to be more than a notification kind — auto-subscribe made it a new synced entity with its own migration.
- **Search** — "Surfaces" commits to "search/filtering". Filtering shipped in `issue-core`; search did not. Closed by change 13: an on-device pass that answers on the keystroke with no network, a Postgres full-text pass that extends it with comment bodies and other teams' issues, and a `/search?q=` route beside the palette. The gap's own evidence — `grep -rn "ilike|tsvector|to_tsquery"` over `apps` and `packages` returning nothing — no longer holds.
- **PR state driving issue status** — the "Wedge proof" line above has promised it since day one. `connectors` built the road up to the last inch: a PR is linked, and `computeDivergence` *flags* a status that disagrees with git rather than correcting it. Nothing wrote a status. That gap had its own evidence too — `grep -rn "auto-status|automatic status" apps packages` returned nothing — and it had produced a repo that contradicted itself in four places at once, with the wedge line promising transitions while both ROADMAP §Post-v1 and VISION §Phase 2 listed them as unstarted Phase 2 work. Closed by change 14, on the maintainer's terms: **opt-in per team, off by default, divergence unchanged when off.** All four sentences now agree.

Changes 11–13 closed the first two. They were scoped — sequence, overlaps, constraint checks, falsifiable checks, and the decisions that need a human — in [`openspec/SCOPE-v1-gaps.md`](openspec/SCOPE-v1-gaps.md), which was the mission input for those three build flows. Change 14 was scoped on its own, against the archived specs, because its gap was a contradiction in the docs rather than a missing surface. What remains is AI *features* on the change-9 foundation (the governed PM-facing digest, the **AI-facilitated** retro drafting on top of the retro that now exists), not core project management.

Order rationale: schema-risk first (2–3 define the work graph's core tables), daily-use surfaces before periphery, connectors before AI, and both last because they bind to stable issue semantics and a rich work graph. `design-system` was inserted after workspace-auth (design pass before the first product screens). Within 11–13: `notifications` owns the write seam and the mailer both others depend on; `mentions` then uses that seam — planned as a new `kind` and nothing else, until the maintainer's answer on auto-subscribe added a durable `issue_subscription` table and migration `0014_mentions` (so `search` takes `0015`); `search` is last because its plaintext walker extends the mention-aware one `mentions` already shipped in `packages/schema/src/rich-text/`, and its central risk (write amplification, and zero-cache replicating past a large GIN index) cannot be measured until it exists. Both resolved when it did: the H10 answer removed write amplification entirely by moving index maintenance off the write path, and zero-cache was verified to replicate cleanly past `search_document` and its GIN expression index from empty volumes, with no publication change.

## Known gaps

Tracked so they are not forgotten — promises made in prose that the code does not yet keep.

- **One-command export.** README ("Your data. One-command export, no lock-in") and VISION #5 both promise it; nothing implements it. TECHSTACK's self-host section makes the adjacent commitment (`yapm backup` → pg_dump + attachments tarball, "documented from day one") — also unimplemented. These are one change, and "free means free" leans on them: export is what makes the no-lock-in claim verifiable rather than rhetorical. **Still unscheduled**, but half its substrate now exists: `attachments` (15) wrote the backup contract down and shipped it as a documented manual procedure — what a complete backup contains per provider, the files-then-database capture order and its inverse on restore, and the `attachment` table as the manifest an S3 operator verifies their own bucket backup against (see [Backup and restore](../apps/docs/src/content/docs/self-hosting/backup-restore.md)) — while `editor-markdown` builds and proves the serialiser it would need. What is left for the change itself is the command that automates them.

## Differentiation commitments

- **Issue list shows reality, not just intention** — rows carry a delivery signal (PR/CI/review) and a divergence flag derived from the work graph; see [DESIGN.md](DESIGN.md). Layout built in `issue-core`; git data populates via `connectors`; and with `auto-status` a team can opt in to having the reality *correct* the intention instead of only flagging it.
- **Connectors, not special-cases** — GitHub is the first implementation of a reusable first-party framework; GitLab and others follow as connectors.
- **AI as a moat is AI-over-the-work-graph** — BYO-key, self-hosted, provider-agnostic, operating under the same permission model as humans (which is also the safety story). Architected from the start, shipped once the graph is rich.

## Post-v1 (from VISION.md phasing)

- **Phase 2 — Delivery truth**: CI/deploy ingestion, DORA + review-health + CI-health views (team-level only). Lights up the issue-list reality strip's full signal. *(Automatic status transitions were listed here and have moved out: the opt-in, per-team form shipped in change 14. Only deploy- and CI-driven transitions, which need an issue↔deployment edge that is not modelled, remain Phase 2 — and are not currently planned.)*
- **Phase 3 — Incidents + cloud**: incident tracking (change failure rate, MTTR), managed cloud offering.
- Backlog of deliberate deferrals: full multi-color theme editor, "blocked-on" issue axis, estimates, sub-issues, additional connectors (GitLab, Jira/Linear import), true third-party plugin runtime, mobile/desktop apps, i18n, public API expansion, Yjs collaborative descriptions.
