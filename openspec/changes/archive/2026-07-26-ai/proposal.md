## Why

`connectors` (#8) lit up the work graph — issue ↔ PR ↔ CI ↔ deploy are now linked, team-scoped, synced entities — and shipped a provider-neutral, server-only, AES-256-GCM encrypted-secrets/config surface explicitly "designed provider-neutral so the AI change reuses it." This change — roadmap #9, `ai` — is the **AI foundation**: a BYO-key, provider-agnostic gateway plus the reusable *AI-over-the-work-graph* substrate, proven end-to-end by one deliberately-minimal flagship consumer (a team-internal, read-only cycle digest). It serves the ROADMAP differentiation commitment "**AI as a moat is AI-over-the-work-graph**" — self-hosted, BYO-key, operating under the *same* permission model as humans (which is simultaneously the code-reuse story and the prompt-injection defense), and differentiated by the **data (the linked work graph), not the model**. It serves VISION #4 (**team-level, never surveillance** — enforced in schema, not copy), #5/#6 (**free + three containers** — no new service, no paywalled capability; AI is BYO-key), and #3 (**reality over ritual** — the digest narrates git truth, never a hand-typed status).

Like `connectors`, it ships infrastructure **validated by its first real consumer** rather than as a speculative abstraction: the cycle-digest MVP exercises every substrate seam (team-scoped narrowed query → grounded typed output → evidence links → pre-compute at cycle close → AI-off fallback), so the foundation is proven correct by use.

## What Changes

- **A provider-agnostic BYO-key gateway** behind a thin yapm wrapper: the Vercel AI SDK v7 (`ai`, Apache-2.0 → AGPL-safe) with the Anthropic/Google/OpenAI adapters, exposing exactly `runAgent(...)` (tool-calling loop under a ceiling), `generateStructured(...)` (grounded typed output), and `resolveModel(...)`. Text + tool-calling + **typed structured output** + streaming, uniform across all three providers. All SDK calls and the decrypted key live in `apps/server`; typed output schemas, the tool registry, and query shapes live in `packages/schema`.
- **Per-workspace BYO-key config reusing the connectors encrypted-secrets surface** — **no new table, no new crypto, no new container**: one `connector_config` row (`provider = "ai"`, an enabled flag, a `config` blob of default provider + per-provider model + optional spend cap) and each provider's API key as a `connector_secret` (`key = "anthropic" | "google" | "openai"`, AES-256-GCM at rest, server-only, never synced). An admin (`canManage`) settings UI over the existing server-only admin REST surface: enable/disable, write-only masked key entry, model choice per provider + workspace default, optional spend cap.
- **The agent-as-actor model**: one AI-SDK tool per yapm mutator, `inputSchema` = the mutator's existing exported Zod args schema, `execute` calling the *same* mutator the human UI calls under an `AuthContext` derived from the invoking user → the role ceiling is automatic and is the primary injection defense; reads exposed as read-only tools over the named queries under the same `ctx`; **writes `needsApproval`-gated (human-in-the-loop), never auto-applied**; least-privilege `activeTools` per task; the loop bounded by `stepCountIs`, run server-side on pg-boss, and audited (actor = agent, on-behalf-of = user).
- **The shared AI-over-work-graph substrate** (build once, features reuse): team-scoped narrowed query → grounded **cite-evidence-or-omit** typed output (a validator drops any item with empty `evidenceRefs`) → evidence links to issue/PR/check/deploy entities → **numbers computed by yapm, not the model** → graceful **AI-off fallback** (render the raw linked evidence). Plus the **injection architecture** (break the lethal trifecta structurally): **no outbound network egress** from the AI step (no web/fetch/HTTP tools; provider `urlContext`/`googleSearch`/`codeExecution`/`mcpServers`/`computerUse` left off), **structured output only**, **numbers-by-yapm**, and **team-level aggregation** (the model is fed only team-level aggregates and structurally cannot name an individual), with a deterministic **name-validator** backstop, delimited-untrusted-text handling, and render-safety.
- **The flagship: a team-internal, read-only cycle digest** consuming the substrate — a new team-scoped, Zero-synced `cycle_digest` artifact (typed sections + evidence-linked items) **pre-computed at cycle close** via the existing pg-boss cycle-maintenance trigger from the cycle's Done/carried issues + linked PR/CI/deploy data, rendered on the cycle view (team members read it; NOT the governed PM-facing version). AI off / no key / outage / spend-cap → the surface renders the raw linked-evidence table instead.
- **Spend surfacing**: per-run estimated cost + per-workspace running total from a small, updatable server-side model+price table (model IDs/prices are **volatile — runtime config, never hardcoded**), labeled "estimated"; optional spend cap refuses to start a run past it.
- **Dependencies**: add `ai`, `@ai-sdk/anthropic`, `@ai-sdk/google`, `@ai-sdk/openai` to the pnpm catalog (all Apache-2.0), used only in `apps/server`. Tests use the SDK's **mock provider** — no real API calls, no key needed to build/test.

## Capabilities

### New Capabilities

- `ai-gateway`: the provider-agnostic BYO-key gateway (Vercel AI SDK v7 behind the `runAgent`/`generateStructured`/`resolveModel` wrapper; per-workspace provider+key+model config reusing the connectors encrypted-secrets surface; the admin settings UI; volatile model/price resolution; per-run + running-total spend surfacing and the optional spend cap; absent config ⇒ AI cleanly disabled, boot never crashes).
- `ai-agent`: the agent-as-actor model (tool-per-mutator registry generated from `defineMutators`, `execute` under the invoking user's `AuthContext`, reads auto-run, writes `needsApproval`-gated HITL, least-privilege `activeTools`, `stepCountIs`-bounded server-side loop, audited) **and** the shared AI-over-work-graph substrate (team-scoped narrowed query → grounded cite-evidence-or-omit typed output → evidence links → numbers-by-yapm → AI-off fallback) with the injection architecture (no egress, structured-only, team-level aggregation, name-validator, delimited untrusted text, render-safety).
- `cycle-digest`: the team-internal, read-only cycle-digest flagship (the `cycleFactsForTeam` team-aggregate query, the team-scoped synced `cycle_digest` artifact, the pre-compute-at-cycle-close pg-boss job, the cycle-view render with evidence links, and the AI-off raw-evidence fallback).

### Modified Capabilities

- `self-host-deploy`: the optional AI provider env (instance-default provider keys + a pre-compute toggle), Zod-validated and optional — absent env disables AI cleanly and never crashes boot; adds no container. The AI gateway runs in-process (SDK call from the app); pre-compute uses the existing pg-boss.
- `local-first-sync`: the new team-scoped, Zero-synced `cycle_digest` artifact replicates under the team scope with row-level permissions and is client-read-only (written only server-side by the pre-compute job); the schema-drift test covers the new table; AI provider keys/config reuse the existing **server-only** connector surface and are never synced.

## Impact

- **Schema** (`packages/schema`): forward-only migration `0010_ai` (the team-scoped synced `cycle_digest` table); the `DB` interface + Zero schema for it (drift test extended); the typed digest output schema + the cite-evidence-or-omit validator + the name-validator; the `cycleFactsForTeam` team-aggregate narrowed query; the tool-registry generator over `defineMutators` + read-tool wrappers over the named queries; the server-side model+price table + spend math; the server-only `cycle_digest` accessor. Docs (`apps/docs`): a self-hoster **AI setup** page (enable AI, enter a provider key, choose a model, the optional instance-default env + `SECRETS_ENCRYPTION_KEY`, spend/cost notes, BYO-key privacy), and a user-facing **Cycle digest** feature page (what it summarizes, evidence links, AI-off fallback), both linked from the sidebar/home; `pnpm --filter @yapm/docs build` passes. ## Non-goals

- **The governed PM-facing digest** (the permission bridge). The two-switch opt-in disclosure, pre/post redaction, path→product-area map, `system`-authority principal, audit, and PM-audience mapping are a separate follow-on change (`pm-digest-bridge`). #9 ships only the **team-internal, read-only** digest under the ordinary role ceiling — no new disclosure model.
- **The retro features** (data-informed retro board and AI-facilitated retro). Later changes that also consume this substrate.
- **Write-back agents beyond HITL.** The agent-as-actor write path is built and `needsApproval`-gated, but the shipping flagship (the digest) is **read-only**; auto-applied writes are never introduced.
- **Streaming UI polish.** The gateway supports streaming; the digest is a pre-computed batch artifact, so a progressive-fill UI is deferred.
- **Managed/hosted agent loops** (Anthropic `beta.agents`, OpenAI-compat shims, LangChain/LlamaIndex). Rejected — they break the self-hosted, acts-via-yapm-mutators-under-the-caller's-ceiling thesis. The loop runs in `apps/server`.
- **A second AI secret store or a per-individual metrics table.** AI keys reuse the connector surface; the team-level guarantee is enforced by the absence of any per-person dimension in the model's context, not by policy.
