## Why

Every retrospective tool on the market — EasyRetro, Retrium, TeamRetro, Metro Retro, Miro, and Parabol (the credible AGPL peer) — opens on a **blank whiteboard** and asks the team what happened. yapm already knows: cycles record what shipped and what carried, and the connectors work graph records how it got there. This change ships the **data-seeded retro**: the Derby & Larsen "Gather data" phase arrives *already filled* from the work graph, the board is deliberately small, and every action item becomes a **real issue in the next cycle** instead of a forgotten doc.

The one-liner: *every other retro tool asks the team what happened; yapm already knows.*

It serves VISION **#3 Reality over ritual** (the retro is seeded by delivery truth, and its output lands in the work graph), **#4 Metrics for teams, never surveillance** (team-level aggregates only, blameless copy, and — the crux — anonymity enforced at the **storage layer**, not by a UI toggle), **#7 Free means free**, **#9 Sub-100ms** (cards, votes and grouping are Zero rows with optimistic writes), and **#10 Keyboard-first**.

It is also a recomposition, not new infrastructure: the board's dnd-kit + fractional-index single-write move, the issue list's keyboard model, cycles and their pg-boss auto-rollover trigger, and the connectors work graph all already exist. The genuinely new surface is narrow — a phase state machine, an anonymity boundary, and a coarse presence/timer.

## What Changes

- **A `retro` entity**, team-scoped and anchored to a cycle, owning a phase state machine — `brainstorm → group → vote → discuss → actions → closed`. Transitions are **enforced in the server mutators**, one step forward or one step back, facilitator/admin only: a client cannot skip or rewind a phase by crafting a mutation, and every write mutator re-checks the retro's *current* phase before it applies.
- **🔴 Anonymity as a storage-layer guarantee.** Zero has no column-level read permission — a synced row is fully readable in every client's IndexedDB, so "strip the author on display" is a privacy bug. Therefore, from day one: the author of a card lives in **`retro_card_author`, a server-only table absent from the Zero schema entirely**, and an anonymous `retro_card`'s synced row carries **no author column value at all**. Clients are structurally unable to learn it. A test enumerates every synced query and proves a non-author member cannot obtain it through any of them.
- **Private brainstorming, by construction.** Cards are written during `brainstorm` as `retro_draft` rows whose only synced query is filtered to `authorId = ctx.userID` (no args, no admin bypass) — so you literally cannot receive someone else's in-progress card. Advancing out of `brainstorm` **publishes** drafts into `retro_card` (same client-minted id, so nothing is minted inside a mutator), writing the server-only author row and setting `authorDisplayId` to null for anonymous retros.
- **The board**: `retro_column` rows (so formats are column-sets, not code) across four starter formats; `retro_group` clustering by drag, reusing the board's **single-write fractional-index move**; dot voting with a server-enforced per-person budget where **voter identity is never synced to anyone but the voter** and clients read a synced `retro_vote_tally` (Zero has no aggregates); a durable `timer_ends_at` counted down locally; coarse `retro_presence` heartbeat rows pruned by the existing pg-boss pass. Keyboard-first throughout, every action also in the command palette.
- **The data-seed panel — the differentiator.** **Delivered** works TODAY with no connectors, from cycles alone: shipped, carried out, carried in, carried **twice or more**, added mid-cycle, canceled — each as a trend against prior cycles with a blameless, system-narrating caption. **Flow** lights up when connectors are present: median PR cycle time, median time-to-first-review, review rounds, issues with no linked PR, and CI failing rate (speed and stability always shown together). **Health** (DORA / MTTR) is Phase 3 — the seam exists, nothing is built. The panel degrades gracefully to whatever data exists, and any widget can seed a card carrying an evidence ref back to the issue/PR it came from.
- **The action → issue loop.** `retro.convertActionToIssue` creates a **real issue through the same creation path any human uses** — team-scoped, assignee set, `cycleId` = the next cycle, per-team number claimed in the same server-authoritative pass — then back-references it so the retro shows live issue status. Auto-rollover then handles an unfinished retro action like any other issue.
- **Auto-open on cycle completion**, reusing the existing auto-rollover pg-boss pass and the deliberate Complete-cycle action — **no new scheduler, no new container**. Idempotent: one retro per cycle, enforced by a unique index and a no-op guard.
- **Two small additions to `issue`** that the Delivered panel needs and nothing else can reconstruct: `carryover_count` (incremented by the existing rollover) and `cycle_assigned_at` (stamped when an issue is put in a cycle), making "carried twice or more" and "added mid-cycle" true facts rather than guesses.

## Capabilities

### New Capabilities

- `retrospective`: the retro entity and its cycle anchor; the server-enforced phase state machine and per-phase write matrix; private brainstorm drafts and the publish step; the storage-layer anonymity boundary (server-only author table, no author on an anonymous synced card, vote-tally-only reads); columns/formats, drag grouping via the shared fractional-index single-write move, dot voting with a server-enforced budget, durable timer and coarse presence; the auto-seeded team-level data panel (Delivered today, Flow with connectors, Health deferred) with blameless captions and evidence-anchored cards; the action → native-issue loop; the keyboard-first, tokenized retro surface correct in all three presets in light and dark; viewers read-only.

### Modified Capabilities

- `cycles`: completing a cycle — by the deliberate action or the pg-boss maintenance pass — SHALL also open that cycle's retro exactly once, through the same call-site-minted-id path, without adding a scheduler; the maintenance pass additionally prunes stale retro presence rows. The rollover SHALL increment each carried issue's `carryover_count`.
- `issue-tracking`: `issue` gains `carryover_count` and `cycle_assigned_at`; a retro action SHALL become a tracked issue through the same shared issue-creation mutator, permissions, and server-authoritative numbering as any human-created issue — never a parallel write path.
- `local-first-sync`: the retro tables replicate under the same team scope with row-level permissions; `retro_draft` and `retro_vote` sync **only to their own author/voter** (no workspace-admin bypass); `retro_card_author` is server-only and excluded from the Zero schema; the drift test covers every new table, column, and exclusion.

## Impact

- **Schema** (`packages/schema`): forward-only migration `0012_retro` — `retro`, `retro_column`, `retro_draft`, `retro_card`, `retro_group`, `retro_vote`, `retro_vote_tally`, `retro_action`, `retro_presence`, the server-only `retro_card_author`, plus `issue.carryover_count` / `issue.cycle_assigned_at`; the Kysely `DB` interface and the hand-written Zero schema extended in lockstep; drift test extended (including the `retro_card_author` Zero-exclusion assertion); retro synced queries; the retro mutator set + the `retro.advancePhase` / `retro.convertActionToIssue` / `retro.startTimer` server overrides; pure modules for the phase machine, the write matrix, the format templates, and the data-seed panel.
- **Server** (`apps/server`): `runCycleMaintenance` gains retro auto-open and presence pruning; no new job type, no new env var, no new container.
- **Web** (`apps/web`): `/teams/$teamId/retros` and `/teams/$teamId/retros/$retroId`, the retro board (columns, cards, grouping, voting, timer, presence), the data-seed panel, the actions list with convert-to-issue, the view-switch/Cycles-view entry points, and the command-palette + keyboard bindings.
- **Dependencies**: none added — dnd-kit, fractional indexing, pg-boss and Zero are already in the catalog.
- **Docs**: a user-facing **Retrospectives** page (`apps/docs/src/content/docs/features/retrospectives.md`) under Features covering the phases, anonymity guarantee, the data panel's graceful degradation, the action→issue loop, and the keyboard map; added to the Starlight sidebar and linked from the docs home; `pnpm --filter @yapm/docs build` passes. Root docs updated: `README.md` (status + feature list), `ROADMAP.md` (the change row + Phase-2 status). `TECHSTACK.md` and `.env.example` are unchanged **by design** — no new dependency and no new env var — and the proposal says so to keep the no-stale-docs check honest. Behavior is specified in `openspec/specs/retrospective`.

## Non-goals

- **Any AI drafting or facilitation.** No AI-proposed cards, no auto-grouping, no narrative summary. That is the later `retro-ai-facilitation` change on the #9 substrate; this change only leaves the seams (the team-level seed model as the agent's input contract, the draft table as the propose-not-decide write path, and evidence refs on cards).
- **DORA / MTTR / incident health metrics** — Phase 3. The panel's Health section is a documented seam that renders nothing today.
- **Real-time collaborative text** (Yjs/OT on a card body), pixel-level presence cursors, and infinite-canvas/drawing chrome.
- **Per-individual anything** — no per-person metric, table, column, leaderboard, or scorecard, in the panel or anywhere else.
- **Reveal-on-close of anonymous authors**, a custom-format template editor, additional formats (Sailboat/Starfish/KALM/DAKI), async multi-day facilitation niceties, and "removed from scope" in the Delivered panel (not reconstructable without an assignment event log).
