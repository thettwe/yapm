# yapm AI Layer — Design + Build Plan (change #9 and the features on top)

**Date:** 2026-07-25. **Status:** plan for the orchestrator to execute autonomously once `connectors` (#8) merges. Everything here that describes unbuilt behavior is a **PROPOSAL**; model IDs/prices are **VOLATILE** (resolve live, never hardcode).

**Grounding (all read for this plan):** `VISION.md`, `ROADMAP.md`, `DESIGN.md`, `CLAUDE.md`, `PROCESS.md`, `openspec/specs/` + `openspec/changes/connectors/` (current built + in-flight behavior), `reference/ai-providers.md`, `reference/connectors.md`, and the scratchpad research: `retro-synthesis.md`, `retro-ai-facilitation.md`, `retro-implementation.md`, `retro-data-informed.md`, `pmdigest-synthesis.md`, `pmdigest-ai-design.md`, `pmdigest-permission-bridge.md`.

**One-line thesis (from ROADMAP Differentiation commitments):** *AI as a moat is AI-over-the-work-graph* — BYO-key, self-hosted, provider-agnostic, an agent that reads via the **same Zero synced queries** and acts via the **same mutators under the invoking user's `AuthContext`**, so the permission ceiling is simultaneously the code-reuse story and the prompt-injection defense. The AI is differentiated by the **data (the linked work graph), not the model.**

---

## 1. The AI foundation change (#9) — concrete, buildable design

The foundation is **four buildable pieces plus one flagship proof**: (1a) the provider-agnostic BYO-key gateway behind a thin wrapper; (1b) BYO-key config reusing the connector secret surface + an admin settings UI; (1c) the agent-as-actor model (tools = mutators under the caller's ceiling, HITL on writes); (1d) the shared *AI-over-work-graph pipeline* substrate every feature reuses, with its injection architecture; and (§2) a deliberately-minimal flagship (the cycle-digest MVP) that exercises the whole pipeline end-to-end so the abstraction is validated by a real consumer, exactly as `connectors` shipped its framework validated by the GitHub connector.

Boundary placement mirrors `connectors` exactly (verified in `reference/connectors.md` §5 and the `connectors` design.md): **Zod schemas, query shapes, typed output schemas, and the tool-registry generator live in `packages/schema`** (no UI/SDK deps); **all `ai`-package calls, the decrypted key, and the pg-boss orchestration live in `apps/server`.** ZQL/mutators never leak; the AI calls mutators, not raw ZQL.

### 1a. Provider-agnostic BYO-key gateway (Vercel AI SDK v7, behind a thin yapm wrapper)

- **Library (verified in `reference/ai-providers.md` §0, §2, adversarial pass):** `ai` 7.0.37 (Apache-2.0) as the gateway core, with `@ai-sdk/anthropic` 4.0.19, `@ai-sdk/google` 4.0.23, `@ai-sdk/openai` 4.0.20 adapters. All Apache-2.0/MIT → **AGPL-safe** (the load-bearing de-risk vs the historical PowerSync/Convex FSL rejection). All ESM, plain `.d.ts`, slot into `apps/server` on Node 24 / TS7 with no toolchain friction. Add to the pnpm catalog (`catalog:` per CLAUDE constraint #5).
- **Capabilities covered uniformly across all three providers (type-verified):** text (`generateText`), tool-calling (`tool({description, inputSchema: z.object, execute, needsApproval?})` with the SDK-run multi-step loop, bounded by `stopWhen: stepCountIs(n)`), **structured output** (`generateObject`/`streamObject` with a Zod schema), and streaming (`streamText`). Per-call BYO-key: `createAnthropic({ apiKey })` / `createGoogleGenerativeAI({ apiKey })` / `createOpenAI({ apiKey })`, constructed **per request from the decrypted secret** — never from env, never cached in a browser-reachable place.
- **The thin yapm wrapper (PROPOSAL, mirrors TECHSTACK's Zero-wrapping discipline).** Put every `ai`-package call behind a narrow, swappable `packages/schema`-typed + `apps/server`-implemented seam exposing exactly:
  - `runAgent(workspaceId, userCtx, { system, messages, tools, activeTools })` — the tool-calling loop under a ceiling (§1c),
  - `generateStructured(workspaceId, userCtx, { system, input, schema })` — the substrate's grounded typed-output call (§1d),
  - a `resolveModel(workspaceId, provider)` that reads the workspace's configured provider/model.
  This keeps the provider gateway one swappable seam. **Documented escape hatch:** drop to the raw first-party SDK (`@anthropic-ai/sdk` etc.) if the AI SDK's `providerOptions` passthrough ever fights a needed provider feature (the LCD surface — text/tools/streaming/structured — is uniform; the per-provider tail e.g. Anthropic `effort`/thinking is not fully type-checked — `reference/ai-providers.md` §2c, open item #3).
- **Model IDs are VOLATILE — never a constant.** Resolve live via each provider's models/list at config time; keep a small, easy-to-update **server-side model+price table** (used for spend estimation, §1e) rather than hardcoded IDs/prices. Default a workspace to a cheap/fast model (digest/retro drafting is a bounded summarize-and-structure task, not a reasoning marathon).
- **Reject Managed Agents / hosted loops.** Anthropic's `client.beta.agents` runs the loop + tools on Anthropic infra, breaking "acts via the SAME yapm mutators under the invoking user's permissions, self-hosted" (`reference/ai-providers.md` §1a). The loop runs **in `apps/server`.** Also reject OpenAI-compat shims (lossy tool/thinking semantics) and LangChain/LlamaIndex (heavy trees, contra PRINCIPLES).

### 1b. Where keys live (reuse the connector encrypted-secrets surface) + admin settings UI

- **No new secret store — reuse what `connectors` (#8) already built.** The `connectors` proposal/spec (verified in `openspec/changes/connectors/`) ships `connector_config`, `connector_secret` (AES-256-GCM at rest via Node stdlib `crypto`, `iv‖tag‖ciphertext`, `SECRETS_ENCRYPTION_KEY`), and `connector_installation` as **server-only Postgres tables excluded from the Zero schema**, and explicitly states they are "designed provider-neutral so the AI change reuses it for provider API keys." #9 therefore adds an `ai` provider dimension to the **existing** surface: a per-workspace `ai_config` row (enabled flag, per-provider default model, optional spend cap) in/alongside `connector_config`, and each provider's API key as a `connector_secret` row (`provider = "ai:anthropic" | "ai:google" | "ai:openai"`). **Adds no table, no container, no new crypto.**
- **The single most important storage rule (`reference/ai-providers.md` §4a):** the BYO-key **must never enter a Zero-synced query or the SPA bundle** — Zero replicates synced rows to every client's IndexedDB. Keys are read **only** in `apps/server`, decrypted into server memory for the duration of one call. This falls out for free by reusing the server-only connector surface.
- **Absent = AI disabled, never crash boot** (mirror the `connectors` optional-env pattern and CLAUDE convention: Zod-validated at startup, failing fast by variable name; an unconfigured provider is simply absent, never paywalled). No key for a provider → that provider is absent from the picker; no key at all / toggle off → no agent tools mount, the AI UI is hidden, and every feature shows its AI-off fallback (§4).
- **Admin settings UI (`canManage`-gated).** Extend the **existing** admin connector settings view (built in #8) with an AI section over the same **server-only admin REST surface** (secrets never sync, so config is fetched/mutated via REST, not Zero — same pattern connectors already uses): enable/disable toggle; per-provider key entry (write-only, shown masked); model choice per configured provider + a workspace default; optional spend cap. Only admins configure; the capability to *use* AI features is role-gated below that (§1c).

### 1c. The agent-as-actor model (tools = mutators, under the invoking user's ceiling)

The safety story **is** the architecture story (`reference/ai-providers.md` §3, verified against `packages/schema/src/zero/{context,mutators,queries}.ts`):

- **The substrate already exists and enforces authz server-side.** `AuthContext { userID, role }` with `canWrite`/`canManage`; every mutator's first act is an assertion against `ctx`; **identity is always from `ctx`, never from args**; queries `denyAll` non-members and team-scope reads through membership.
- **One AI-SDK `tool` per yapm mutator; `inputSchema` = the mutator's existing exported Zod args schema** (e.g. the connectors/issue mutator arg schemas already exported from `packages/schema`) — no parallel schema. The tool registry is **generated from `defineMutators`** so the model can never call anything a human couldn't. Reads are exposed as read-only tools over the named `queries`, each running under `ctx` so `denyAll` masks out-of-scope data.
- **`execute` calls the same mutator the human UI calls, passing an `AuthContext` derived from the invoking user → automatic role ceiling.** A viewer's agent gets a viewer ctx → every write mutator throws → read-but-not-mutate. A member's agent can write but not manage. There is no separate "agent permission" system to get wrong. (Open, deferred: an optional `agentScopes` narrowing *below* the human's role — least-privilege even below role — recommended later, not required for v1 correctness.)
- **Human-in-the-loop for writes (first-class in the SDK):** write/destructive tools default to `needsApproval: true` → the loop pauses on a `ToolApprovalRequest` the user confirms in-UI before it runs; reads auto-run. **Least-privilege tool set per task** via `activeTools` — a "summarize this cycle" run gets read tools only, never `member.changeRole`.
- **The loop runs server-side on pg-boss, bounded by `stepCountIs`; every agent-initiated mutation is audited** (actor = agent, on-behalf-of = user), fitting yapm's soft-delete/undo posture.

### 1d. The shared "AI-over-work-graph pipeline" substrate (build once; both digest and retro reuse it)

This is the reusable core the PM digest and both retro features template on top of. Build it **once** in #9 (`pmdigest-synthesis.md` §4, `retro-ai-facilitation.md` §4, `pmdigest-ai-design.md` §8 all independently converge on this exact substrate):

1. **Team-scoped narrowed query.** A dedicated, narrowed read shape (`cycleFactsForTeam(teamId, cycleId)`) that emits **team-level aggregates only** — counts, medians, rates, trends, per-issue evidence bundles — **with no `assignee`/`author`/`reviewer`/`user_id` dimension.** This is a separate, narrower query than the general work-graph read, reusing yapm's existing (already team-level) metric computations, so the AI inherits "team-level only" for free.
2. **Grounded, typed structured output — cite-evidence-or-omit.** Output is a **Zod-typed object** via `generateStructured` (not prose to parse): sections + per-item `{ kind, summary, evidenceRefs[], confidence }`. A **validator rejects any item with empty `evidenceRefs`** — a claim the model cannot attach to a linked signal is not emitted. This is enforceable *because* the output is schema-typed.
3. **Evidence links to work-graph entities.** Every emitted item links its issue / PR / check / deploy entity (which the reader can open), never to raw code. Trust comes from one-click verifiability, not authority.
4. **Numbers computed by yapm, not the model.** Counts (14/16 shipped, 3 carried), labels, CI conclusions, review medians are **computed by yapm**; the model only *narrates* them. Kills the "invented a metric" hallucination class. Each item carries `confidence: high|medium|low`.
5. **Graceful AI-off fallback (mandatory for every consumer).** With AI off / no key / provider outage / spend-cap hit, the surface renders the **raw linked evidence** it already has (issues + linked PRs + CI/deploy status + scope delta) as a plain table/panel — strictly more than the reader has today, never blocking anything. The AI narrative is an **enhancement layer on a surface that stands alone.**

**The injection architecture, baked into the substrate (not per-feature policy).** The moment the AI reads external attacker-influenceable text (PR bodies, commit messages, comments, CI logs from `connectors`), the "lethal trifecta" (private data + untrusted content + exfiltration) is live. The substrate **breaks a leg of the trifecta architecturally**, per `reference/ai-providers.md` §3d and `pmdigest-permission-bridge.md` §6.2:

- **No outbound network egress from the AI step.** The pipeline mounts **no external-communication tools** — no web/fetch/email/arbitrary HTTP, and the provider-side `urlContext`/`googleSearch`/`codeExecution`/`mcpServers`/`computerUse` tools are left **off**. Output goes only to the in-yapm typed artifact. (Removes the exfiltration leg.)
- **Structured output only.** The model emits a typed object through a fixed schema — no free-form channel to smuggle instructions-as-output.
- **Numbers computed by yapm, not the model** (as above) — the model narrates verified facts, it doesn't originate consequential data.
- **Team-level aggregation → structurally can't name individuals.** The identity dimension is never in the model's context, so even a fully injected model cannot call out a person (§4). A deterministic **name-validator backstop** rejects any output containing a workspace member's name/handle before it's shown.
- **Permission ceiling is the primary defense** (§1c): a fully injected agent can only do what the invoking user could, and writes are `needsApproval`-gated → worst case is a bad *paragraph*, never a bad *action*.
- **External text is delimited, labeled untrusted data — never concatenated into the system prompt as instructions.** Trusted operator authority uses the non-spoofable operator/system channel only.
- **Render-safety:** the artifact UI must not auto-load remote images/links from summarized content (the Markdown-image exfil class) — sanitize on render.

### 1e. Cost / latency (it's the user's key)

- **Pre-compute off the hot path via pg-boss.** A digest/retro draft is a batch, non-interactive job (seconds of aggregation + one structured-output call), nowhere near the sub-100ms interaction budget (CLAUDE constraint #9). **Pre-compute on cycle completion** using the *existing* pg-boss trigger that already runs cycle auto-rollover (ROADMAP #5), so the artifact is ready when the cycle is opened — the click feels instant. On-demand variants run interactively as a normal `runAgent` call. Long runs are rate-limited per workspace so a slow model call never blocks a request; streaming rides the existing Hono SSE layer.
- **Surface spend — the user pays.** Every provider returns per-call usage; the AI SDK normalizes it (`LanguageModelUsage`, per-step usage on `steps`). Multiply usage × the volatile server-side price table → show **estimated** per-run cost + a per-workspace running total, labeled "estimated." Optional spend cap refuses to start a run past it. (`reference/ai-providers.md` §4c.)

## 2. What ships in #9 vs later feature changes — recommendation

**Recommendation: #9 ships the gateway + config + agent-as-actor model + the shared substrate AND ONE deliberately-minimal flagship — the *team-internal, read-only cycle-digest MVP* — but NOT its governed permission-bridge surface.** The heavy PM-facing governance (two-switch opt-in disclosure, pre/post redaction, path→area map, audit, PM-audience mapping, a `system`-authority principal) is a **separate follow-on change** (`pm-digest-bridge`, §3-B).

**Why include a flagship at all (not gateway-only):** yapm's own established pattern is to ship infrastructure **validated by its first real consumer**, not as a speculative abstraction. `connectors` (#8) shipped the connector *framework* together with the GitHub connector as "its first implementation" — the ROADMAP is explicit about this. The AI-over-work-graph substrate (§1d) is only *proven correct* — its query shape, typed schema, evidence-link model, and AI-off fallback — by running one real feature through it end to end. Shipping the gateway with zero consumers would violate the codebase's own "build once, validated by use" discipline and leave an untested abstraction.

**Why the cycle-digest MVP is the right flagship (and why *minimal*):**
- It is the **cheapest complete exerciser** of the whole pipeline: team-scoped narrowed query → `generateStructured` typed output → evidence links → pre-compute at cycle close on pg-boss → AI-off raw-evidence fallback. It touches every substrate seam.
- Keep it **read-only** in #9 (it *reads and summarizes*; it does not write mutators), so the first cut proves the read pipeline + structured output + injection architecture without also debugging the HITL-write path in the same change. (The retro's action-item→issue write path, with `needsApproval`, is exercised later in §3-D.)
- Keep it **team-internal** in #9 (visible to the team that owns the cycle, under the ordinary role ceiling). This needs **no new disclosure model** — no redaction, no two-switch, no `system` principal. That entire security surface is exactly what makes the *PM-facing* bridge heavy, and it belongs in its own change where it can get the security scrutiny it demands (`pmdigest-permission-bridge.md` is a whole design's worth of controls).

**Net split:**
- **#9 `ai`:** gateway + BYO-key config/UI + agent-as-actor tool model + shared substrate + **cycle-digest MVP (team-internal, read-only)** as the proof.
- **Later features:** the governed PM permission bridge (B); the data-informed retro board (C, needs no AI); the AI-facilitated retro draft (D, needs #9 + C).

This keeps #9 focused ("BYO-key work-graph AI, proven by the internal cycle digest") while still validating the abstraction with a real consumer, and it quarantines the two genuinely hard security surfaces — cross-audience disclosure (B) and AI drafting under injection (D) — into their own reviewable changes.

## 3. Build-plan / change breakdown (dependency order)

Each item below is a proposed OpenSpec change (`openspec/changes/<name>/` with proposal → design → specs → tasks, per PROCESS.md §1). Test tiers follow the **big-feature rule** (PROCESS.md §3): all three tiers (unit + integration + E2E) iff the change touches ≥2 of {synced entity/schema, mutator, permission surface, signature UI}.

### A. `ai` (ROADMAP #9) — the AI foundation + cycle-digest MVP proof

- **Scope (one paragraph):** The BYO-key, provider-agnostic gateway (Vercel AI SDK v7 behind the thin `runAgent`/`generateStructured` wrapper; Anthropic/Gemini/OpenAI; text + tool-calling + structured output + streaming), reusing the `connectors` encrypted-secret surface for per-workspace keys (adds an `ai` provider dimension, no new table/container) with an admin settings UI (`canManage`) over the existing server-only admin REST surface; the agent-as-actor tool model (one tool per mutator, `inputSchema` = the mutator's Zod args, `execute` under the invoking user's `AuthContext`, reads auto-run, writes `needsApproval`-gated, loop bounded by `stepCountIs`, audited); the shared AI-over-work-graph substrate (team-scoped narrowed query → grounded cite-or-omit typed output → evidence links → numbers-computed-by-yapm → AI-off raw fallback) with the injection architecture (no egress, structured-only, team-level aggregation, name-validator, delimited untrusted text, render-safety); and the **team-internal, read-only cycle-digest MVP** as the flagship that runs the whole pipeline and pre-computes at cycle close via the existing pg-boss trigger.
- **Hard prerequisites:** `connectors` (#8) merged — for the encrypted-secret surface **and** for the work-graph data (linked PRs/CI/deploy) the digest reads; `issue-core` (#3, done) + `cycles` (#5, done) for the mutator/query set and the cycle-close trigger.
- **Research feeding the spec:** `reference/ai-providers.md` (gateway, agent-as-actor, cost, injection §3d — the primary source); `reference/connectors.md` §6 (secret surface reuse); `pmdigest-ai-design.md` §§3–6 + `pmdigest-synthesis.md` §4 (the digest pipeline, accuracy controls, MVP-vs-later split — take only the **team-internal, non-governed** MVP here).
- **Test-tier needs:** **All three.** It adds a config/secret surface + AI provider dimension (schema), the tool-registry-over-mutators path (mutator/permission surface), and a signature settings UI + digest view. Unit: model resolution, cite-or-omit validator, name-validator, spend math, tool-registry generation, tool ceiling predicates. Integration (live PG + zero-cache): admin config authz end-to-end, "key never in a synced query" assertion, agent-under-viewer-ctx cannot write, digest pre-compute job. E2E: admin configures a (mocked-provider) key → toggles on → opens a completed cycle → sees the digest; toggle off → AI-off evidence fallback renders; keyboard flow. **Test against a mocked provider** (recorded responses), mirroring connectors' mocked-GitHub strategy — no live model calls in CI.
- **Key risks:** prompt injection via ingested PR/commit text (mitigated architecturally, §1d — the load-bearing risk); hallucinated "what shipped" (cite-or-omit + computed numbers + confidence + one-click verify); cost surprise on the user's key (cheap-model default, estimated-cost display, spend cap); provider model-ID/price volatility (resolve live, updatable table); `providerOptions` passthrough tail not fully typed (validate the specific options used, keep the raw-SDK escape hatch).

### B. `pm-digest-bridge` — the governed PM-facing permission bridge

- **Scope (one paragraph):** Turn #9's team-internal digest into the **governed cross-audience disclosure** a PM without repo access can read: two independent switches default-OFF (`connector.ingest.enabled` vs `digest.pmVisible.enabled` — ingesting a repo must not auto-expose it to PMs); per-team PM-audience mapping; pre-model secret-scan + path/file denylist and post-model output re-scan (defense-in-depth redaction); an **altitude contract** system prompt (business-level only — no file paths/symbols/snippets/architecture — which is also the trade-secret firewall); transient diff fetch via the install token then discard (yapm never becomes a second copy of source); a **`system`/`connector`-authority pipeline** (read authority = the admin-configured connector/App scope, disclosure authority = the admin's policy — resolves that the PM's own ctx has no repo grant; extends the `ctx` model with a system principal + its own audit identity); provenance stamp + retention bound + kill switch + full audit log; product-area grouping, the risk/divergence section, on-demand variants (per-issue, per-project, "explain this change", custom range), and export.
- **Hard prerequisites:** `ai` (#9) — the substrate + digest MVP it extends; `connectors` (#8) — App-held repo access + transient diff fetch (`pulls.listFiles`).
- **Research feeding the spec:** `pmdigest-permission-bridge.md` (the whole controlled-disclosure model, three-tier trust boundary, admin governance surface, "safer than a repo grant" framing, injection/exfil §6.2 — primary); `pmdigest-ai-design.md` (signals, correlation, output design, accuracy controls); `pmdigest-synthesis.md` (competitive whitespace, verdict, MVP-vs-later).
- **Test-tier needs:** **All three.** Adds the two-switch + audience-mapping schema, a system-principal on the mutator/permission surface, and a signature PM digest view + admin governance UI. Unit: redaction pre/post filters, altitude-contract output validation (no path/symbol leaks), two-switch gating logic. Integration: `digest.pmVisible` OFF keeps a repo in the graph for engineers but out of PM disclosure; system-principal read authority = connector scope; audit-log completeness; retention purge. E2E: admin opts a repo into PM visibility → PM (viewer) sees the abstracted digest, never code; kill switch; export.
- **Key risks:** over-disclosure / code leaking through the abstraction (layered: no code field in schema, pre+post redaction, altitude contract, opt-in default-off, team-level — bounded, not zeroed; the honest comparison is still "far less exposure than a repo grant"); prompt-injection exfil (same architecture as §1d — no egress tools + redaction weakens the private-data leg); the disclosure gap closing from adjacent directions (move while the cell is empty); legal/trade-secret sign-off is per-org (ship the capability + controls, each org's counsel judges its sensitivity); scope drift toward a customer changelog (keep it internal, cycle-scoped, risk-aware).

### C. `retro-board` — the data-informed retrospective board + data panel (NO AI required)

- **Scope (one paragraph):** A cycle- and team-scoped retro meeting object with a phase state machine (`brainstorm → group → vote → discuss → actions → closed`, facilitator/admin may step back one), live via Zero (cards/votes/grouping are "just rows" — optimistic writes + reactive queries + the board's existing dnd-kit + fractional-index single-write moves); **anonymity done correctly at the storage layer** (Zero has no column-level read permission, so an anonymous card's author is stored in a **server-only, non-synced `retro_card_author` table** and never shipped to clients; votes keep `voter_id` server-only and sync only an aggregate tally); a durable-end-time timer (no per-tick broadcast); coarse presence-as-rows pruned by pg-boss (no sidecar — preserves 3 containers); 3–4 starter formats as swappable column-sets; the **auto-seeded data panel** (Delivered from cycles today; Flow/Health widgets as connectors data lands — team-level, trend-first, blameless captions); and the **action-item → native next-cycle issue** loop via the same issue-creation mutator humans use. **This change needs no AI and ships fully without it** — the data panel is a live Zero query, not a model call; it degrades to a manual data-informed retro.
- **Hard prerequisites:** `cycles` (#5, done) + `issue-core` (#3, done) for the board itself and the action→issue loop. `connectors` (#8) is a **soft** prerequisite — it only enriches the Flow/Health widgets; the Delivered panel and the whole board work from cycle data alone.
- **Research feeding the spec:** `retro-implementation.md` (entity/phase model, Zero real-time, the anonymity storage crux, action→issue, keyboard/theming — primary); `retro-synthesis.md` (verdict, differentiation, guardrails, format set, MVP-vs-later); `retro-data-informed.md` (which widgets, blameless framing, Goodhart guardrails).
- **Test-tier needs:** **All three.** Adds the retro entity family (schema), phase-gated + anonymity-stripping + vote-budget + convert-to-issue mutators (mutator/permission surface), and a signature board UI. Unit: phase legality, vote-budget math, fractional-index moves, format→column seeding. Integration: **anonymity is real** — assert the author is absent from every client-facing synced query / not in the client replica; vote tally syncs but `voter_id` does not; phase races rejected server-side; convert-to-issue lands in the next cycle. E2E: multi-client card/vote/group convergence, keyboard flows, anonymity end-to-end, action→issue with live status.
- **Key risks:** **anonymity is a privacy bug if done wrong** (server-only author table is non-negotiable, not a UI courtesy — the one place the feature can quietly betray yapm's trust promise); surveillance drift (encode team-level-only in the schema — no per-individual table — not docs); scope creep toward whiteboard sprawl (keep the board small; the *data seed* is the wow, not board chrome); thin seed until connectors (sequence with/after #8 so Flow/Health aren't empty); genuinely optional for a 2–20 team (must never displace the wedge).

### D. `retro-ai-facilitation` — AI-drafted Wins/Losses/Improvements over the retro board

- **Scope (one paragraph):** The AI reads the cycle's **team-level** work-graph slice via the #9 substrate and drafts a small (≤3–4/bucket), schema-typed, evidence-linked, confidence-flagged straw-man in three buckets (Wins / Losses / Improvements) into the retro board; the team **ratifies card-by-card** via per-person agree/disagree with hidden tallies and a threshold model (agreed → accepted with no mandatory discussion; contested/any strong-dissent → routed to discussion; rejected → dropped and logged to an "AI got this wrong" feedback log); humans add their own cards with equal standing (ideally a silent-write-first mode to counter anchoring); an agreed Improvement is promoted to a **native next-cycle issue** through the mutator, `needsApproval`-gated (reads auto-run, writes confirm); the blameless/no-individual guarantee is enforced by the substrate's team-level query (no per-person data reaches the model) + a blameless system prompt + the name-validator; and it degrades to Change C's manual data-informed retro when AI is off.
- **Hard prerequisites:** `ai` (#9) — the substrate + agent-as-actor write path (this is where the HITL `needsApproval` create-issue tool is first exercised); `retro-board` (C) — the board, phases, and action→issue loop it drafts into.
- **Research feeding the spec:** `retro-ai-facilitation.md` (the agree/disagree design, three-layer blameless guardrail, propose-not-decide, MVP-vs-later, risks — primary); `retro-synthesis.md` §3 (AI as a later enhancement layer on the retro); `reference/ai-providers.md` §2a/§3 (structured output, `needsApproval`).
- **Test-tier needs:** **All three.** Reuses C's schema/board but adds the AI draft path + the ratification mechanic (mutator/permission surface) and signature draft-and-ratify UI. Unit: card schema validation, cite-or-omit + name-validator on drafted cards, threshold classification, blameless-rewrite check. Integration: draft runs under team-level query (no identity in context — assert), agreed-Improvement→issue requires approval, viewer's agent can draft but not create issues. E2E (mocked provider): draft appears at cycle close → per-person react → contested routes to discussion → agreed → HITL-approve → issue in next cycle; AI-off falls back to manual.
- **Key risks:** anchoring bias (small hedged draft, silent-write-first mode, one-click disagree, equal-standing human cards); hallucinated findings (cite-or-omit grounding, structured output over computed facts, clickable evidence); prompt injection via PR/issue text (permission ceiling + writes-approved + team-level query + name-validator + no egress + delimited untrusted text); trust cost of a wrong card (evidence links show it read real data; confidence hedging; the "AI got this wrong" log as trust-repair + tuning signal).

### Sequencing & overlap

```
#8 connectors ──▶ #9 A: ai (gateway+config+substrate+digest MVP) ──┬──▶ B: pm-digest-bridge
                                                                    └──▶ D: retro-ai-facilitation
#5 cycles ─────────────────────▶ C: retro-board (no AI) ───────────────▶ D (also needs C)
```

- **C (`retro-board`) needs no AI and can run in parallel with #9** on a separate git worktree (PROCESS.md §5) — it touches disjoint surfaces (new retro tables + Zero board) from #9 (server AI + config). This is the safe overlap: C ships a lovable data-informed retro first, de-risking the differentiator, then D lands the AI draft on a foundation that already works.
- **B and D both consume the #9 substrate**, so both come after A. **B and D can overlap with each other** (B = server disclosure pipeline + governance + PM view; D = retro board + AI draft — disjoint surfaces), but **D also requires C**, so C must precede D. Natural order if run mostly-serially: **A → (C in parallel with A) → B and D (D after C).**
- Ship the data-consuming features **with or after connectors** so they launch with a real seed, not an empty promise.

## 4. Cross-cutting guardrails (shared infra, encoded not documented)

These are non-negotiable and, per CLAUDE.md, enforced in CI — a change that violates one is wrong even if it works. Build them **once** as shared infra the features inherit, not per-feature policy.

1. **Team-level / blameless / no-individual-surveillance — a *schema-level* guarantee.** VISION #4 and CLAUDE constraint #8: metrics are team-level only, never individual leaderboards. Encode it in **storage**, not copy: **no per-individual metrics table exists in the schema**; the AI substrate's read is a dedicated **team-aggregate query with no `assignee`/`author`/`reviewer`/`user_id` dimension**, so even a fully injected model *cannot* name a person (the identity data is never in its context); a deterministic **name-validator** rejects any output containing a workspace member's name/handle; and the retro's anonymity is a **server-only author/voter table that never syncs** (Zero has no column-level read permission, so "strip on display" would be a privacy bug). "Our AI literally cannot name you" is a verifiable claim in AGPL source.
2. **Injection architecture (break the lethal trifecta architecturally, not by "please ignore injections").** Applied to every AI step (§1d): **no outbound network egress** from the AI step (no web/fetch/email/HTTP tools; provider `urlContext`/`googleSearch`/`codeExecution`/`mcpServers`/`computerUse` left off); **structured output only** (typed schema, no free-form channel); **numbers computed by yapm, not the model**; **team-level aggregation** (can't name individuals); **permission ceiling as primary defense** (an injected agent can only do what the invoking user could; writes `needsApproval`-gated → worst case a bad paragraph, never a bad action); **external text delimited + labeled untrusted**, never concatenated as instructions; **bounded loop** (`stepCountIs`); **render-safety** (no auto-loading remote images/links). Residual (injection can *bias the narrative*) is contained to the accuracy problem, not a leak or an action.
3. **BYO-key degradation — absent = disabled, never crash, always a fallback.** Mirror the connectors optional-env pattern: keys Zod-validated at boot, failing fast by name; **no key / toggle off / provider outage / spend-cap hit → AI disabled cleanly**, no agent tools mount, AI UI hidden, and **every feature degrades to its AI-off surface** (digest → raw linked evidence table; retro → manual data-informed board). The AI is always an *enhancement layer on a surface that stands alone.* Cost is the user's: estimated-spend display + running total + optional cap. "Free means free" (CLAUDE #7): AI is BYO-key, never a paywalled capability.
4. **Three-container constraint — all AI runs in-process, no new service.** CLAUDE constraint #1 (`app` + `zero-cache` + `postgres`, nothing else): the agent loop runs **in `apps/server`** (Hono + pg-boss) — **not** the client (the decrypted key must never reach the browser or a synced query), **not** Anthropic-hosted (Managed Agents rejected — it would break the self-hosted, acts-via-yapm-mutators thesis). Pre-compute uses the **existing** pg-boss instance (already running cycle rollover + connector webhooks); streaming rides the **existing** Hono SSE; presence/timer for the retro stay in Postgres/pg-boss (no Redis/WS sidecar). **The AI layer adds no dependency beyond the four Apache-2.0/MIT npm packages and no container.**
